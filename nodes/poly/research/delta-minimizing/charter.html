Poly Copy-Trade Delta Charter

Goal

Systematically drive |delta| = |our_position − scaled(target_position)| to zero across all watched (target, market) pairs. /delta-minimizer investigates ONE incident at a time and produces ONE proven cause. This charter is the rollup: every proven cause lands here, scored, and linked to a design item. Without that aggregation we keep re-investigating the same class of bug under different surface symptoms.

How to use this charter

  • When /delta-minimizer produces a finding: add or update a row in the projects/taxonomy below. Cite the incident (market + tape).
  • When triaging a new bug: read the taxonomy first. If the symptom matches a known class, link to the existing class instead of creating a new ticket.
  • When designing a fix: the design item must reference a class (or argue for a new one).

A new class is added only when the failure mode is structurally distinct — same gate, different price → same class. Different gate or different data structure assumption → new class.

Constraints

What blocks driving the table to green:

  • Single execution surface. Today's pipeline is fill-driven end-to-end (planMirrorFromFill). Any class that isn't dissolvable by adding a per-fill gate (D2/D3/D4/D6) requires the position-mirror refactor. No incremental in-place fix for those.
  • Chain RPC dependency. D1's solution (chain source, task.5043) makes the mirror hard-dependent on POLYGON_RPC_URL. If that RPC degrades, the mirror is silent — a single point of failure we accept v0 in exchange for sub-second target detection.
  • No live regression test. Replaying a recorded tape (e.g. swisstony WTA Parma) against a candidate planner change is not wired. Each design iteration is validated against synthetic logs + production observation only. Adding a tape-replay harness is itself a project on this charter, not yet listed.
  • Capital cap of $30/trade (v0). Even when delta-classes are dissolved, absolute P/L impact is bounded by mirror_max_usdc_per_trade. This charter measures _delta minimization_, not _P/L maximization_ — those will diverge until v1.

Working agreements

1. No new gate is added to plan-mirror.ts without a charter entry naming the delta class it addresses. We are over-indexed on per-fill gates already; adding more without classifying the bug they target is how we ended up here.

2. Every /delta-minimizer proof updates this charter before the user-facing reply ends. Either a row gets added or an existing row's "proof tape" list grows. Otherwise we re-litigate.

3. When a class moves to 🟢 SHIPPED, the row stays in the table with a Shipped: <PR / SHA> note in the Status column. The shipped class is still a category — it's how we measure regression.
